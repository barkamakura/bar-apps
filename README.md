# Bar KAMAKURA 業務アプリ

店舗運営用の3つのWebアプリ。GitHub Pages で公開し、iPad・スマホのホーム画面から
アプリとして起動できます（暗証番号ロック・オフライン対応つき）。

公開URL: https://barkamakura.github.io/bar-apps/

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | 暗証番号ロック＋3アプリを切り替えるまとめ画面（ここが入口） |
| `price.html` | ① 値段確認アプリ（料理／お酒／お酒(ボトル)）※お酒は**税抜**を入力し、税込10%で原価計算 |
| `slip.html` | ② 伝票アプリ（卓ごとの注文・合計金額・お会計） |
| `records.html` | ③ 売上記録アプリ（お会計済み伝票の集計・明細） |
| `manifest.json` | ホーム画面アイコン・全画面起動の設定 |
| `sw.js` | オフラインでも画面が開くようにする仕組み |
| `icon-*.png` | アプリアイコン各サイズ |
| `.nojekyll` | GitHub Pages の余計な変換を止めるための空ファイル |

## 暗証番号について

`index.html` の中の `PIN_HASH` に、暗証番号のSHA-256値だけを保存しています
（番号そのものはコードに書かれていません）。

一度正しく入力すると、その端末では次回から入力不要になります。
別の端末で開いた場合や、ブラウザのデータを消した場合はもう一度聞かれます。

### 番号を変えたいとき

1. 新しい4桁の番号のSHA-256値を出す（「SHA256 変換」で検索すれば計算サイトが使えます）
2. `index.html` の `PIN_HASH = "..."` の中身を差し替える
3. 保存して push

※ このロックは「玄関の鍵」であって「金庫」ではありません。
URLを知られただけの人は入れませんが、技術に詳しい人がページのソースを
解析すれば突破できます。本格的に守るならデータ保存先ごと作り直しが必要です。

## ホーム画面に追加する手順

**iPhone / iPad (Safari)**
1. Safariで公開URLを開く
2. 下（またはアドレスバー横）の共有ボタン → 「ホーム画面に追加」
3. アイコンから起動すると、アドレスバーなしの全画面で開きます

**Android (Chrome)**
1. Chromeで公開URLを開く
2. 右上のメニュー → 「アプリをインストール」または「ホーム画面に追加」

## お酒の値段計算について

「お酒」タブの「1本の値段」は **税抜(本体価格)** を入力します（仕入書のとおりの金額）。
アプリが消費税10%を足した**税込の金額**から1杯あたりの原価を出し、その約5.7倍(原価率17.5%)を
販売価格にします。700円以下は700円、超えたら100円単位で四捨五入。

酒類は軽減税率の対象外なので10%です。税率が変わったら `price.html` の
`const TAX_RATE = 0.10;` を書き換えてください。
原価率を変えたいときは同じく `price.html` の `const COST_RATE = 0.175;` を書き換えます
(0.175 = 17.5% → 約5.7倍。表示の「原価率17.5%換算(約5.7倍)」も自動で変わります)。

※この変更より前に登録した品目は、登録時の(税抜ベースの)販売価格のまま残ります。
更新したい品目は一度削除して登録し直してください。

## 品目の並び順(伝票アプリ・値段確認アプリ 共通)

伝票アプリの品目ピッカーと、値段確認アプリの「お酒」「お酒(ボトル)」の一覧は、
どちらも **ジャンルごと → 値段の安い順 → 同じ値段の中は五十音順** で並びます。
ひらがな・カタカナは同じ扱い(「あかし」と「アカシ」は同じ位置)、数字も自然な順(2年→10年)です。
漢字だけの名前は読み仮名が判定できないため五十音順にはなりません(その値段帯の最後のほうにまとまります)。

並び順を変えたいときは `slip.html` の `byPriceThenNameJa` と、`price.html` の `groupByCategory` を直します。
(「料理」タブは登録した順のままです)

## 画面の並び(v19)

- **伝票**: 合計金額 → 「＋追加」ボタン → 注文内容 → 卓一覧に戻る／お会計
- **卓一覧**: 卓を選択 → 未提供の注文(受注順)

## 提供の管理(v17で追加)

注文を伝票に入れると、その注文は**未提供**の状態で入ります。

- **卓一覧の「卓を選択」の下**に「未提供の注文(受注順)」が出ます(v19で位置変更)。古い注文が上、卓名・品名・経過時間つき。
  ここの「提供」ボタンを押すと提供済みになります。
- **ドリンクとフードで分けて表示**します(v18)。バーなのでドリンクが上。
  ドリンク＝お酒／お酒(ボトル)／ショット／カクテル、フード＝おつまみ・料理。
  判定は `slip.html` の `DRINK_CATS` です。
- **伝票の注文一覧**でも、未提供の注文は黄色くなり「提供」ボタンが出ます。
  押し間違えたときは「戻す」で未提供に戻せます。
- 卓ボタンにも「未提供◯」と出ます。
- お会計画面を開いたとき、未提供が残っていると上に注意が出ます(押せなくはしていません)。

データは各注文の `served`(true/false) と `servedAt` に入ります。
**この機能より前に入っていた注文は `served` を持たないので「提供済み」扱い**にしています
(過去の注文が大量に未提供として出てこないようにするため)。

※他のiPadで入れた注文は自動では出てきません。上の「🔄 更新」を押すと最新になります。

## 追加したときの合図(v18)

割材や飲み方の選択がない品目(ビール・ワイン・ソフトドリンク・ホットドリンク・ボトル・おつまみ・料理)は
タップした瞬間に一時リストへ入るため、反応が分かるようにしています。

- 画面下に「◯◯ を追加しました」と1.5秒ほど出ます
- タイルの色が変わり、`×2` のように今いくつ入れたかが出ます

## カクテル・ショット欄の場所(v17)

カクテル(おすすめ／シェイク／季節)とショットの欄は、**「お酒」タブのときだけ**出ます。
「お酒(ボトル)」「おつまみ・料理」タブには出ません。

## 割材・飲み方の選択が出ないジャンル(v16)

**ビール / ワイン / ソフトドリンク / ホットドリンク** は、タップするとそのまま一時リストに入ります
(水割り・ロック・ストレート・割材の選択画面は出ません)。
対象は `slip.html` の `NO_MODS_CATEGORIES` で決めています。

## 個数(v15で追加)

品目をタップすると「今回追加する項目」に**1点**として入り、そこで **＋ / −** で個数を変えられます。
同じ品目・同じ飲み方をもう一度タップした場合は、行が増えずに個数が1つ増えます。
「伝票に追加」を押すと、伝票側には**1杯ずつ別の行**として入ります(あとから1杯だけ取り消せるようにするため)。

## カクテル(v15で整理)

伝票アプリのカクテル欄は3つです。

| ボタン | 値段の決め方 |
| --- | --- |
| おすすめカクテル | その場でスタッフが800〜1500円から選ぶ(値段確認アプリでの登録は不要) |
| シェイクカクテル | 同上 |
| 季節のカクテル | 値段確認アプリの「季節のカクテル」タブで登録した名前と値段から選ぶ |

「季節のカクテル」はショットと同じく、**＋ / − で数量**を決めてから追加します。
＋を連打しても画面が先頭に戻らないよう、押した行だけを書き換える作りにしています(v16)。
データは今までの `cocktails` キーをそのまま使っています。

## ショット(v14で追加)

値段確認アプリの「ショット」タブで、**名前と値段を自由に設定**して登録します。
伝票アプリでは品目ピッカーの「カクテル」欄の下に「ショット」欄が出ます。
タップすると登録したショットが並び、**＋/− で数量**を決めて、下の「追加」で伝票に入ります。
割材や飲み方の選択はありません。

## おつまみ・料理のジャンル分け(v14で追加)

値段確認アプリの「おつまみ・料理」タブでは、登録時に **おつまみ / 料理** のジャンルを選びます。
伝票アプリの同名タブでも、そのジャンルごとに分かれて表示されます。

ジャンルを設定する前に登録した品目は「未分類」にまとまります。
一覧の「ジャンル」欄のメニューから選べば、登録し直さずに分類できます。

## データの保存先

3アプリとも jsonbin.io の同じ bin を共有しています。

- `menuItems` … 値段確認アプリ
- `slips` … 伝票アプリ／売上記録アプリ
- `shots` … ショット(値段確認アプリ／伝票アプリ)
- `deletedSlips` … 売上記録アプリの消去フォルダ
- `reservations` … 予約確認アプリ（別ページ）

各アプリは読み込み時にレコード全体を保持し、自分が使うキーだけを上書きして保存します。

オフラインのときは画面は開きますが、データの読み書きはできません（ネット必須）。

## 更新のしかた

ファイルを書き換えて push すると、1〜2分で公開URLに反映されます。
`sw.js` の `CACHE = "bk-app-v1"` の番号を上げると、端末に残った古い画面が確実に入れ替わります。
