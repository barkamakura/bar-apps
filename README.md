# Bar KAMAKURA 業務アプリ

店舗運営用の3つのWebアプリ。GitHub Pages で公開し、iPad・スマホのホーム画面から
アプリとして起動できます（暗証番号ロック・オフライン対応つき）。

公開URL: https://barkamakura.github.io/bar-apps/

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | 暗証番号ロック＋3アプリを切り替えるまとめ画面（ここが入口） |
| `price.html` | ① 値段確認アプリ（料理／お酒／お酒(ボトル)）※お酒は**税抜**を入力し、税込10%で原価計算 |
| `slip.html` | ② 伝票アプリ（卓ごとの注文・合計金額・お会計） |
| `records.html` | ③ 売上記録アプリ（お会計済み伝票の集計・明細） |
| `manifest.json` | ホーム画面アイコン・全画面起動の設定 |
| `sw.js` | オフラインでも画面が開くようにする仕組み |
| `icon-*.png` | アプリアイコン各サイズ |
| `.nojekyll` | GitHub Pages の余計な変換を止めるための空ファイル |
| `denpyo-uriage/` | **伝票＋売上記録の2つ入りアプリ**(v25)。中に index.html / slip.html / records.html / manifest.json / sw.js / アイコン |

## アプリの入口は2つ(v25)

用途に合わせて2つの入口があります。**どちらも同じデータ(jsonbin)を見ています。**
片方で作った伝票は、もう片方でもそのまま見えます。

| 入口 | URL | 中身 | アイコン |
| --- | --- | --- | --- |
| まとめアプリ | `https://barkamakura.github.io/bar-apps/` | 値段確認・伝票・売上記録の3タブ | ロゴのみ |
| 伝票・売上記録アプリ | `https://barkamakura.github.io/bar-apps/denpyo-uriage/` | 伝票・売上記録の2タブ | ロゴ＋オレンジの「伝票・売上」 |

営業中のiPadは2つ入りのほう、商品の登録や値段の計算をするときはまとめアプリ、という使い分けを想定しています。
**値段確認アプリはまとめアプリの中にだけあります。**

暗証番号は共通で、同じ端末なら1回入れればもう一方も解錠済みになります(`localStorage` はサイト単位のため)。

`denpyo-uriage/` の中の `slip.html` / `records.html` は、ルートのものと**中身が同じコピー**です。
**片方だけ直すとズレます。直したら必ず両方に配ってください。**

> v24で作った `denpyo/`(伝票だけ)と `uriage/`(売上記録だけ)の単独アプリは、v25で**廃止**しました。
> リポジトリに残っている場合は「Delete directory」で消してください。

## 営業日の区切り(17時)(v24)

売上記録アプリの集計・絞り込みは、**17時を1日の始まり**として数えます。

- 「9月1日」の売上 = **9月1日 17:00 〜 9月2日 16:59**
- なので深夜2時のお会計は、その日ではなく**前の日**の売上になります
- 日別・月別・年別のすべてがこの区切りです(10月1日の深夜2時 → 9月の売上)
- 一覧の各行と明細に「営業日 ◯/◯」が出るので、実際のお会計時刻と見比べられます

区切りの時刻を変えたいときは `records.html` の `const DAY_START_HOUR = 17;` を書き換えてください
(`uriage/records.html` も同じように直すこと)。

## 暗証番号について

`index.html` の中の `PIN_HASH` に、暗証番号のSHA-256値だけを保存しています
（番号そのものはコードに書かれていません）。

一度正しく入力すると、その端末では次回から入力不要になります。
別の端末で開いた場合や、ブラウザのデータを消した場合はもう一度聞かれます。

### 番号を変えたいとき

1. 新しい4桁の番号のSHA-256値を出す（「SHA256 変換」で検索すれば計算サイトが使えます）
2. `index.html` の `PIN_HASH = "..."` の中身を差し替える
3. 保存して push

※ このロックは「玄関の鍵」であって「金庫」ではありません。
URLを知られただけの人は入れませんが、技術に詳しい人がページのソースを
解析すれば突破できます。本格的に守るならデータ保存先ごと作り直しが必要です。

## 日本酒(v29で追加)

お酒のジャンルに **日本酒** を足しました。焼酎とリキュールの間に入ります。

- **値段確認アプリ**: ウイスキーなどと同じく、**1本の容量 / 1杯の量 / 1本の値段(税抜)** から自動計算します
  (例: 720ml・1杯90ml・税抜2,400円 → 1杯の原価330円 → 販売価格1,900円)
- **伝票アプリ**: 割材も飲み方も選ばず、**タップするとそのまま入ります**(ビールなどと同じ扱い)
- 販売価格が700円以下なら、飲み放題プランでもそのまま頼めます

ジャンルを足したいときは `price.html` と `slip.html` の `LIQUOR_CATEGORIES` を**両方**直します。
割材が要らないジャンルなら、`slip.html` の `NO_MODS_CATEGORIES` にも足してください。

## お酒の値段計算について

「お酒」タブの「1本の値段」は **税抜(本体価格)** を入力します（仕入書のとおりの金額）。
アプリが消費税10%を足した**税込の金額**から1杯あたりの原価を出し、その約5.7倍(原価率17.5%)を
販売価格にします。700円以下は700円、超えたら100円単位で四捨五入。

酒類は軽減税率の対象外なので10%です。税率が変わったら `price.html` の
`const TAX_RATE = 0.10;` を書き換えてください。
原価率を変えたいときは同じく `price.html` の `const COST_RATE = 0.175;` を書き換えます
(0.175 = 17.5% → 約5.7倍。表示の「原価率17.5%換算(約5.7倍)」も自動で変わります)。

※この変更より前に登録した品目は、登録時の(税抜ベースの)販売価格のまま残ります。
更新したい品目は一度削除して登録し直してください。

## 品目の並び順(伝票アプリ・値段確認アプリ 共通)

伝票アプリの品目ピッカーと、値段確認アプリの「お酒」「お酒(ボトル)」の一覧は、
どちらも **ジャンルごと → 値段の安い順 → 同じ値段の中は五十音順** で並びます。
ひらがな・カタカナは同じ扱い(「あかし」と「アカシ」は同じ位置)、数字も自然な順(2年→10年)です。
漢字だけの名前は読み仮名が判定できないため五十音順にはなりません(その値段帯の最後のほうにまとまります)。

並び順を変えたいときは `slip.html` の `byPriceThenNameJa` と、`price.html` の `groupByCategory` を直します。
(「料理」タブは登録した順のままです)

## 画面の並び(v19)

- **新規伝票**: 他の卓へ(v28) → 新規/常連 → 人数 → プラン(8名以上のときだけ) → 任意項目 → 作成(v26)
- **通常の伝票**: 他の卓へ(v28) → 合計金額 → 「＋追加」ボタン → 注文内容 → 卓一覧に戻る／お会計
- **飲み放題の伝票**(v27): 他の卓へ(v28) → 合計金額 → 🍻飲み放題プラン(スタート・時間・注文追加・人数変更) → 注文内容 → 卓一覧に戻る／お会計
- **卓一覧**: 卓を選択 → 未提供の注文(受注順)

## 他の卓へ移るボタン(v28で追加)

伝票の画面と新規伝票の画面の**一番上**に、**今いる卓以外**のボタンが並びます。
押すとその卓へすぐ移れます(空席の卓なら新規伝票の画面へ)。卓一覧に戻らなくて済みます。

- 対応中の卓は**青くなり、今の合計金額**が出ます。空席の卓は「空席」
- 未提供の注文があると、右上に**オレンジの数字**が出ます
- 卓を移るときは、開いていたお会計の画面や品目の画面を自動で閉じます(前の卓の操作が残らないように)

## 飲み放題プラン(v23で追加・v26でプラン選択を追加)

**伝票を作るときにプランを選びます**(v26)。
新規/常連 → 人数 と選んで、**人数が8名以上のときだけ**「プラン(必須)」の欄が出ます。

- **通常** … 今まで通りの伝票(チャージ 1人500円)
- **🍻 飲み放題** … 飲み放題プランつきの伝票

どちらか選ぶまで「この内容で伝票を作成」は押せません(金額が大きく変わるため)。
7名以下のときはこの欄自体が出ず、そのまま作成できます。

作ったあとは、伝票の**合計金額のすぐ下**に「🍻 飲み放題プラン」の欄が出ます(v27で位置を変更)。
スタート・残り時間・延長・注文の追加・人数の変更が全部ここにまとまっています。

**通常で作った伝票には、この欄は出ません**(v27)。プランは伝票を作るときに決めるものなので、
あとから設定したり解除したりはできません。間違えたときは伝票を作り直してください。

飲み放題の伝票では、画面上の「＋追加」ボタンは出ません(v27)。
追加ボタンが2つあると押し間違えるためで、飲み放題の欄の中の2つを使い分けます。

| ボタン | 何が入るか |
| --- | --- |
| ＋ 飲み放題の注文を追加(0円) | 700円以下のお酒・ソフトドリンクだけ。0円で入る |
| ＋ 別途料金で追加する | 飲み放題に入っていない商品。通常の値段で合計に足される |

| 項目 | 内容 |
| --- | --- |
| 人数 | 8名以上(上限なし) |
| 料金 | 1人 4,000円(2時間) |
| チャージ | なし(飲み放題料金に含む) |
| 延長 | 1時間ごとに 1人 2,000円 |
| ラストオーダー | 開始から1時間30分 |
| 注文の締め切り | 開始から1時間40分(ここで飲み放題の追加ボタンが押せなくなる) |

延長すると、ラストオーダーと締め切りも同じだけ後ろにずれます
(常に「終了30分前がLO、終了20分前で締め切り」)。

### 飲み放題で頼めるもの

- 値段確認アプリの**お酒**のうち、販売価格が **700円以下**のもの(ソフトドリンクを含む)
- 割材は **＋100円のもの(600円のソフトドリンク)** だけ。飲み放題では追加料金は取りません
- これらは伝票に **0円** で入り、「飲み放題」のタグが付きます

判定の数字は `slip.html` の `NOMI_PRICE_LIMIT`(700) と `NOMI_MIXER_EXTRA`(100) です。

### 飲み放題以外の注文

飲み放題の欄の下にある「**別途お酒・おつまみ等**」から追加します。
こちらは通常の値段で合計に足されます。飲み放題の伝票では、これが唯一の「通常価格で足す」入口です
(v27で画面上の「＋追加」ボタンは出さなくしました)。

### 時間の管理

- 伝票を作ったあと、提供を始めたタイミングで「**▶ スタート**」を押します
- 押すとその時刻から2時間の計測が始まり、残り時間・終了予定・ラストオーダーが出ます
- 押し忘れたら「**開始時間を修正**」から `20:15` のように入れ直せます
- 「**＋1時間延長**」で延長。押した回数だけ料金と時間が増えます(「延長を1時間戻す」で取り消し)
- 卓一覧の卓ボタンにも「🍻飲み放題 残◯」と出ます

データは `slip.nomihodai = { count, startAt, extends }` に入ります。
このキーが無い伝票は今まで通り(チャージあり)の伝票です。

## 提供の管理(v17で追加)

注文を伝票に入れると、その注文は**未提供**の状態で入ります。

- **卓一覧の「卓を選択」の下**に「未提供の注文(受注順)」が出ます(v19で位置変更)。古い注文が上、卓名・品名・経過時間つき。
  ここの「提供」ボタンを押すと提供済みになります。
- **ドリンクとフードで分けて表示**します(v18)。バーなのでドリンクが上。
  ドリンク＝お酒／お酒(ボトル)／ショット／カクテル、フード＝おつまみ・料理。
  判定は `slip.html` の `DRINK_CATS` です。
- **伝票の注文一覧**でも、未提供の注文は黄色くなり「提供」ボタンが出ます。
  押し間違えたときは「戻す」で未提供に戻せます。
- 卓ボタンにも「未提供◯」と出ます。
- お会計画面を開いたとき、未提供が残っていると上に注意が出ます(押せなくはしていません)。

データは各注文の `served`(true/false) と `servedAt` に入ります。
**この機能より前に入っていた注文は `served` を持たないので「提供済み」扱い**にしています
(過去の注文が大量に未提供として出てこないようにするため)。

※他のiPadで入れた注文は自動では出てきません。上の「🔄 更新」を押すと最新になります。

## 追加したときの合図(v18)

割材や飲み方の選択がない品目(ビール・ワイン・ソフトドリンク・ホットドリンク・ボトル・おつまみ・料理)は
タップした瞬間に一時リストへ入るため、反応が分かるようにしています。

- 画面下に「◯◯ を追加しました」と1.5秒ほど出ます
- タイルの色が変わり、`×2` のように今いくつ入れたかが出ます

## カクテル・ショット欄の場所(v17)

カクテル(おすすめ／シェイク／季節)とショットの欄は、**「お酒」タブのときだけ**出ます。
「お酒(ボトル)」「おつまみ・料理」タブには出ません。

## 割材だけの注文(v21)

伝票の「お酒(ボトル)」タブに、ワイン／シャンパン／その他 の下へ **「割材」** の欄を作りました。
ボトルを入れたお客様が、そのあと割材だけを頼むときに使います。

- 値段確認アプリの**ソフトドリンク**がそのまま並びます(お酒の割材と同じ種類)
- 600円のものは **＋100円**、800円のものは **＋200円** で表示・計算します
- 押すとその場で追加されます(飲み方の選択なし)。伝票には `コーラ(割材)` のように出ます
- 並びは ＋100円 → ＋200円 の順、同額なら五十音順

## 割材の中身を選ぶ(v20)

お酒の飲み方で「割材(+100)」「割材(+200)」を選ぶと、**どの割材かを選ぶボタン**が下に出ます。

- 割材(+100) … 値段確認アプリの**ソフトドリンクで600円**のものが全部並びます
- 割材(+200) … 同じく**800円**のものが並びます

割材を選ぶまで「この内容で追加」は押せません(該当する値段のソフトドリンクが1つも登録されていない場合だけ、
注意文を出したうえで割材の指定なしで追加できます)。

選んだ割材は注文一覧・未提供リスト・売上記録の明細に **割材+200(レッドブル)** のように出ます。
対応は `slip.html` の `MIXER_PRICE_BY_EXTRA`(100→600円 / 200→800円)で決めています。

## 割材・飲み方の選択が出ないジャンル(v16・v29で日本酒を追加)

**ビール / ワイン / 日本酒 / ソフトドリンク / ホットドリンク** は、タップするとそのまま一時リストに入ります
(水割り・ロック・ストレート・割材の選択画面は出ません)。
対象は `slip.html` の `NO_MODS_CATEGORIES` で決めています。

## 個数(v15で追加)

品目をタップすると「今回追加する項目」に**1点**として入り、そこで **＋ / −** で個数を変えられます。
同じ品目・同じ飲み方をもう一度タップした場合は、行が増えずに個数が1つ増えます。
「伝票に追加」を押すと、伝票側には**1杯ずつ別の行**として入ります(あとから1杯だけ取り消せるようにするため)。

## カクテル(v15で整理)

伝票アプリのカクテル欄は3つです。

| ボタン | 値段の決め方 |
| --- | --- |
| おすすめカクテル | その場でスタッフが800〜1500円から選ぶ(値段確認アプリでの登録は不要) |
| シェイクカクテル | 同上 |
| 季節のカクテル | 値段確認アプリの「季節のカクテル」タブで登録した名前と値段から選ぶ |

「季節のカクテル」はショットと同じく、**＋ / − で数量**を決めてから追加します。
＋を連打しても画面が先頭に戻らないよう、押した行だけを書き換える作りにしています(v16)。
データは今までの `cocktails` キーをそのまま使っています。

## ショット(v14で追加)

値段確認アプリの「ショット」タブで、**名前と値段を自由に設定**して登録します。
伝票アプリでは品目ピッカーの「カクテル」欄の下に「ショット」欄が出ます。
タップすると登録したショットが並び、**＋/− で数量**を決めて、下の「追加」で伝票に入ります。
割材や飲み方の選択はありません。

## おつまみ・料理のジャンル分け(v14で追加)

値段確認アプリの「おつまみ・料理」タブでは、登録時に **おつまみ / 料理** のジャンルを選びます。
伝票アプリの同名タブでも、そのジャンルごとに分かれて表示されます。

ジャンルを設定する前に登録した品目は「未分類」にまとまります。
一覧の「ジャンル」欄のメニューから選べば、登録し直さずに分類できます。

## データの保存先

3アプリとも jsonbin.io の同じ bin を共有しています。

- `menuItems` … 値段確認アプリ
- `slips` … 伝票アプリ／売上記録アプリ
- `shots` … ショット(値段確認アプリ／伝票アプリ)
- `deletedSlips` … 売上記録アプリの消去フォルダ
- `reservations` … 予約確認アプリ（別ページ）

各アプリは読み込み時にレコード全体を保持し、自分が使うキーだけを上書きして保存します。

オフラインのときは画面は開きますが、データの読み書きはできません（ネット必須）。
